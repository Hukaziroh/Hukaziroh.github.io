BACK TOGETHER

4인 협동 퍼즐 플랫포머

협동 게임에서는 한 명의 연결이나 상태가 바뀌면 팀 전체의 플레이가 영향을 받습니다. 로비 생성부터 입장, 합체, 종료까지 이어지는 흐름을 담당했습니다.

IMPLEMENTATION

구현과 문제 해결

01

로비 탐색과 게임 연결의 역할 분리

EOS는 방 생성·검색·참가를, Mirror와 EosTransport는 호스트·클라이언트 연결을 담당합니다. SDK 준비 상태와 사용자 ID를 확인한 뒤 로비 생성과 속성 설정을 순서대로 처리하고, 성공 후 호스트를 시작합니다.

  • SDK 준비 대기는 최대 10초, 로비 생성과 속성 설정은 각각 최대 5초
  • Time.unscaledDeltaTime으로 일시정지와 독립된 타임아웃 계산
  • 공개 여부는 IS_PUBLIC, 초대용 코드는 SHORTCODE로 별도 관리
02

서버에서 판정하는 합체 입력과 협동 버튼

PlayerInput이 입력 변경을 Command로 전송하고, PlayerCombineHandler가 myRole·extraRoles에 따라 역할별 입력을 모읍니다. 수평 입력을 합산한 뒤 -1~1로 제한해 본체 이동에 반영합니다. 협동 버튼은 델리게이트 이벤트로 상태 변경을 알리고 기믹이 조건을 판정합니다.

  • 기본 역할과 추가 역할을 같은 HasRole() 기준으로 확인
  • SyncVar 훅·ClientRpc로 합체 외형과 카메라 전환 반영
  • CoopButtonUtility로 구독과 공통 버튼 판정 재사용
03

종료·재접속 상황의 정리 순서

로비 정리보다 네트워크 종료가 먼저 진행되면 빈 방이 검색 목록에 남을 수 있었습니다. Application.wantsToQuit에서 종료를 보류하고 로비 파괴·퇴장을 최대 2초 기다린 뒤 Mirror와 전송 계층을 종료하도록 순서를 바꿨습니다.

  • 사용자 종료 요청의 정리 경로를 추가해 유령방 발생 가능성 감소
  • 접속 ID와 0~3 외형 슬롯을 분리하고 빈 슬롯 우선 할당
  • 중도 참여자는 팀원 위치로 합류하며, 여분 역할이 있을 때 합체에 참여

적용 범위
